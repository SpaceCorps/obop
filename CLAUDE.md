# obop — one business, one platform

Open-source operating system for businesses: an Odoo-class modular suite (ERP, CRM, accounting, inventory, manufacturing, HR, projects, POS, e-commerce, website, marketing, helpdesk, documents) on one shared data model. Clean-room re-implementation of Odoo's concepts and behaviour, not a code port. Apache-2.0 and completely free to use and to self-host.

The owner's rulings of 2026-10-01 (OR-1 to OR-21) and 2026-10-27 (OR-22 to OR-34) are recorded in `docs/DECISIONS.md`, sections "Owner rulings (2026-10-01)" and "Owner rulings (2026-10-27)". They are RATIFIED and win over every Proposed position in every document and in the research. Anything the owner has not ruled stays PROPOSED or open; do not treat it as decided.

## Hard tech constraints (set by the owner)

- **Backend:** exclusively the latest stable Rust (pinned exactly; see the pin policy below). "Exclusively Rust" governs the code obop authors and ships (I-1, RATIFIED, OR-14): PostgreSQL, PgBouncer, OCR engines, CI validators and the like that obop only runs are allowed dependencies, and optional sidecars stay out of the default install.
- **Frontend and tooling:** exclusively the latest Vite+ (`vite-plus`).
  - All JS/TS tooling goes through the **`vp` CLI** (dev, build, test, lint, format, tasks, environment).
  - The package manager is **pnpm**. Never use `npm`, `npx`, `yarn` or `bun`. The only JavaScript lockfile that may exist is `pnpm-lock.yaml` (`Cargo.lock` is committed as usual); `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `bun.lock` and `bun.lockb` must never be committed (CI fails on them). "No npm" means the CLI; pnpm still installs from the public npm registry.
  - Whether obop itself publishes anything to the npm registry (for example `@obop/*` SDK packages) is decided at W2 (OR-19, Q32); until the owner rules, the default is no publication. This file bars the npm CLI only.
  - Research files that describe Vite+ as supporting several package managers are describing the tool, not obop policy. obop uses pnpm only.
- **Three named exceptions to "vp only"** (RATIFIED: the first two by OR-9, I-2, I-4, D15; the third by OR-34, D87):
  1. the nightly exit drill, which runs upstream Vite tools without `vp` in a throwaway copy of the tree that never ships;
  2. `pnpm sbom` for the JavaScript SBOM, run through `vp env exec` or a `vp run` task until `vp` gains an SBOM wrapper (the exception lapses then);
  3. the mobile toolchain of React Native (Expo) apps (the owner said "with the mobile-toolchain exception"; these conditions are its recorded form): Metro, the Expo CLI, Gradle and Xcode cannot be run by Vite+, so they are started through `vp env exec` or `vp run` tasks. pnpm stays the only package manager, and `vp check`, `vp test` and `vp build` still cover every shared TypeScript package.

  There are no other exceptions. In particular `pnpm licenses list` is not one (OR-9; Q33 is answered); read licence fields from the SBOM or go through `vp`.
- **Pin policy** (RATIFIED, D23, I-3, OR-8): "latest" means the newest release that has passed a cooldown of 7 to 14 days, or its `x.y.1` patch. The toolchain therefore intentionally runs up to about three weeks behind the newest release. Pins are exact; the pnpm major is 12.x (OR-28; `package.json` pins `pnpm@12.6.0`). Adopting Rust 1.99.x follows mechanically from this policy and needs no separate ruling. See `docs/DECISIONS.md` section 1.1.

## Licence, price and working rules (set by the owner, RATIFIED)

- **Licence and price** (OR-1, OR-2, OR-22; D1, D2): the whole project is Apache-2.0 and completely free, with no proprietary layer. No open-core, no enterprise tree, no paid features, no paid marketplace or partner programme, no AGPL layer, no CLA. The only planned paid thing is a hosting service run by SpaceCorps (dedicated Sliplane servers at a multiple of Sliplane's price, extra storage extra; OR-22): it is planned, not offered or charged yet, and it restricts nothing in the free software. `LICENSE` and `NOTICE` ("Copyright 2026 SpaceCorps contributors") are at the repository root; every crate (`license.workspace = true`), bundled package (`license = "Apache-2.0"`) and JavaScript manifest declares `Apache-2.0`. A new dependency must be under a licence compatible with Apache-2.0 (no copyleft-only components).
- **Publisher** (OR-10): SpaceCorps is the publisher, copyright holder and trademark holder. The repository `SpaceCorps/obop` is public (opened by the owner on 2026-10-26; gate G0 is overtaken, OR-26; CI runs on GitHub-hosted runners, OR-29). "obop" is a working name until counsel clears it (OR-5).
- **Contributions** (RATIFIED, OR-1, OR-18; D82): DCO sign-off on every commit (`git commit -s`); no CLA. The owner signs off every commit and agents are recorded with a `Co-Authored-By` trailer; agents never add a `Signed-off-by` line. A CI job for the check is not built yet; it comes when outside contributors appear (OR-30). Counsel is still asked to confirm that this satisfies the DCO (a counsel item, not an owner question).
- **Agentic first, CLI for everything** (RATIFIED, OR-4, OR-16; F6, D80): every capability is a typed command reachable through the `obop` CLI, the REST API and MCP. The web UI (React on Vite+, driven through `vp` with pnpm) is a client of the same commands and reaches parity with them before the first stable release. UI parity is literal: every command of every shipped module gets a UI before the first stable release, except operator-only commands (for example backup, doctor, upgrade, pack verify) that the owner approves as CLI-only with a written reason (the exemption list; nothing is exempt until the owner approves it). A feature is not done until it exists in CLI, API and MCP; nothing ships as UI-only. The command grammar and the plugin registry client are specified in `docs/spec/cli.md` (detail PROPOSED until Q22 is answered).
- **Hosting and funding** (RATIFIED, OR-6, OR-11, OR-20, OR-22; D83, D84): the software is free (OR-2). The one planned paid thing is the hosting service of OR-22 (dedicated Sliplane servers at three times Sliplane's price, rounded up to a price ending in 9; planned, not offered or charged yet). Apart from that, SpaceCorps operates no hosted obop for other people today, only one free, ephemeral hosted sandbox with sample data, run by SpaceCorps and opened at the public beta (OR-20, D83; its terms, cost ceiling and abuse approach are PROPOSED, Q34 to Q36). An optional local demo (`obop dev up`) may also exist. The project is self-funded; the team is the owner plus AI agents (OR-6, D84).
