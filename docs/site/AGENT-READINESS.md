# Agent readiness of the website

Vercel's agent-readiness checker, [is-agentic](https://is-agentic.com), scans a public domain and scores how well an AI agent can read and use it. This page maps what the checker looks at to what the obop website does.

- **Status:** working document, 2026-10-16.
- **Honest limits:** the scanner cannot reach `localhost`, so the score has **not** been measured. The owner runs it against the deployed domain (`vp dlx is-agentic <domain>`, a local one-off check, never in CI) and records the result below. The public methodology page describes the scoring (essential checks carry 80 points, recommended 20, emerging formats up to 5 bonus points; checks that do not apply are excluded) and the categories, but does not publish a per-check list, so the table maps the categories and the checks named in the brief, not a verified list of identifiers.
- The behaviours that need the control plane are listed in `SITE.md` under "Server requirements". Items marked **server** below do not pass until that is done.

## Essential

| Area                              | What the checker wants                                               | What the site does                                                                                                                                                                      | Where it is tested                                                            |
| --------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Server-rendered, readable content | The content is in the HTML the server sends, not built by JavaScript | Every page is static HTML. No framework runtime is shipped. View-source shows the real text                                                                                             | `site.spec.ts`: "the home page is real HTML", whole suite with JavaScript off |
| Real HTTP status codes            | 200 for pages, 404 for missing pages, redirects that behave          | Every route is a file. **Server:** unknown paths must answer 404 with `/404.html` (today they fall back to `index.html` with 200), and slashless URLs must redirect                     | `404.html` content test; the status needs the server change                   |
| Clear document structure          | One `h1`, ordered headings, landmarks, semantic elements             | One `h1` per page, no skipped levels, `header`, `nav` (labelled), `main`, `footer`, tables and lists as real elements                                                                   | `site.spec.ts` accessibility tests; every English page checked for one `h1`   |
| Recoverable errors                | A helpful 404 with ways forward                                      | `404.html` explains, has a search box, links to the main pages, `sitemap.xml`, `llms.txt` and the other languages, and asks not to be indexed                                           | "the 404 page is friendly"                                                    |
| Usable, labelled controls         | Controls have accessible names and visible labels                    | Search has a label, the theme and language controls have names, filters are labelled radio groups, copy buttons are named                                                               | `unnamedControls` over eleven pages                                           |
| Identity metadata                 | Canonical URL, declared language, Open Graph tags                    | Per page: canonical, `<html lang>`, `og:title`, `og:description`, `og:url`, `og:image` (generated per page), `og:locale`, Twitter card, `hreflang` and `x-default` for translated pages | "every English page has title, description, canonical, language…"             |
| robots.txt hygiene                | Present, valid, no accidental disallows, sitemap referenced          | Allows everything, names 22 AI crawlers and agents explicitly (GPTBot, ClaudeBot, Claude-User, PerplexityBot, Google-Extended and others), lists both sitemaps, has no `Disallow`       | "sitemap index… and robots.txt"                                               |
| Sitemap                           | `sitemap.xml` that lists the pages                                   | An index of one sitemap per language (with `hreflang` alternates) and the forum's `/community/sitemap.xml`                                                                              | same                                                                          |
| Trust pages                       | Privacy, terms, security, contact, about                             | `/privacy/`, `/terms/` (both marked draft, not legal advice), `/security/` plus `/.well-known/security.txt`, `/contact/`, `/about/`, `/about/status/`, `/about/community/`              | "changelog, roadmap, trust pages…"                                            |

## Recommended and emerging

| Area                                       | What the site does                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llms.txt`                                 | `/llms.txt` follows llmstxt.org: an H1, a blockquote summary, sections of links with one-line descriptions that point to the Markdown versions. `/llms-full.txt` holds the text of every English page                                                                                                                                                                                                          |
| Markdown for agents                        | Every page exists as Markdown at its address with `.md` (front matter: title, description, canonical, language), and every page head has `<link rel="alternate" type="text/markdown">`. **Server:** `Accept: text/markdown` negotiation on the page URL (see `SITE.md`), with `Vary: Accept`                                                                                                                   |
| Structured data                            | JSON-LD: Organization, WebSite with SearchAction (the target is the real `/search/?q=` page), SoftwareApplication for obop and for each of the 28 apps, FAQPage on the home and pricing pages, BreadcrumbList, TechArticle for documentation                                                                                                                                                                   |
| Search                                     | A real `/search/` page that answers `?q=` and a header search that falls back to it                                                                                                                                                                                                                                                                                                                            |
| Language                                   | Seven languages, `hreflang` only for translated pages, no automatic redirect, a dismissible hint instead                                                                                                                                                                                                                                                                                                       |
| API, OAuth, MCP, GraphQL, commerce signals | The marketing site does not publish an API description: obop has no OpenAPI document yet, and none is invented. The documentation describes the REST API, the MCP server (`obop mcp`) and the CLI in prose and in `llms-full.txt`. A remote MCP endpoint and an OpenAPI document are not built; add `/.well-known` entries when they exist. The checker excludes checks that do not apply to a site's evidence |
| Site type declaration                      | The checker documents an `is-agentic-site-type` declaration but its page does not say how it is made. When the owner finds the mechanism, add it in `.vitepress/config.ts` (`head`). Documentation and content site is the right type                                                                                                                                                                          |
| Performance for agents and people          | No render-blocking script, one CSS file, fonts preloaded with `font-display: swap`, no layout shift, tiny JavaScript (theme, search, copy, language hint; the ASCII field on the home page only)                                                                                                                                                                                                               |

## What to do after deploying

1. Make the server changes in `SITE.md` ("Server requirements"): 404 status, slash redirects, `Accept: text/markdown`, content types, caching.
2. Set `OBOP_SITE_URL` to the public origin and rebuild, so canonical links, the sitemap and social cards use it.
3. Run `vp dlx is-agentic <domain>` (or open the site on is-agentic.com), read each failed finding and fix it here.
4. Record the score and date in this file.
