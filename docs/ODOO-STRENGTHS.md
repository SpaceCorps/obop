# Odoo's strong points and how obop covers them

- **Status:** Draft. Every recommendation here is (Proposed). Nothing in this document is decided; the owner rulings in [DECISIONS.md](DECISIONS.md) win over it.
- **Date:** 2026-11-14
- **Repository state:** `main` at `74ad13a5`
- **Audience:** the owner and contributors

## 1. Purpose

The owner was shown a graphic, "Odoo vs SAP B1 feature comparison", made by an Odoo partner (oerp.ca). It is a partner's marketing, not evidence, but its ten rows name things buyers expect, and the owner wants obop to cover all of Odoo's strong points, not only those ten. This document maps 226 strong points in 13 areas to what obop has today and what it plans, as of 2026-11-14 and the repository state `main` at `74ad13a5`. Each point has exactly one status, with evidence paths:

- **built:** working Rust code with tests, reachable through the CLI, the REST API and MCP (and the UI where relevant).
- **package:** provided by a bundled `packages/*.toml` package with Odoo's depth. No point earned it: every package that models a strong point has less depth than Odoo, so it is rated partial.
- **partial:** some of it is built or packaged, but a named part of Odoo's strength is missing.
- **planned:** specified in `docs/spec` or [PRODUCT.md](PRODUCT.md) with a wave, not built.
- **deferred:** explicitly deferred (T3, W4+, community, connector only) or explicitly not planned.
- **missing:** not built and not mentioned anywhere in the docs.

**How to read.**

- Research is cited as R01 s3.2, meaning `docs/research/01-...md` section 3.2: R01 [01-odoo-app-catalog.md](research/01-odoo-app-catalog.md), R02 [02-odoo-architecture.md](research/02-odoo-architecture.md), R03 [03-odoo-business-model.md](research/03-odoo-business-model.md), R04 [04-odoo-voice-of-customer.md](research/04-odoo-voice-of-customer.md), R09 [09-accounting-finance-compliance.md](research/09-accounting-finance-compliance.md), R10 [10-supply-chain-manufacturing.md](research/10-supply-chain-manufacturing.md), R11 [11-crm-sales-subscriptions.md](research/11-crm-sales-subscriptions.md), R12 [12-retail-pos-ecommerce-marketing.md](research/12-retail-pos-ecommerce-marketing.md), R13 [13-hr-payroll.md](research/13-hr-payroll.md), R14 [14-services-project-helpdesk-field.md](research/14-services-project-helpdesk-field.md), R19 [19-ux-design-system.md](research/19-ux-design-system.md), R20 [20-market-personas-mvp-gtm.md](research/20-market-personas-mvp-gtm.md), R28 [28-docs-community-support-brand.md](research/28-docs-community-support-brand.md).
- An Odoo claim not found in the research is marked "general knowledge, unverified".
- CE is Odoo Community, EE is Odoo Enterprise. OR-n is an owner ruling, Dn a decision, Kn, An and On items of [ISSUES.md](ISSUES.md).
- Waves (DECISIONS 5.2; the W1 window is RATIFIED by OR-13, the rest Proposed): W0 2026-10-01 to 2026-12-31, W1 2027-01-01 to 2027-09-30, W2 2027-10-01 to 2028-06-30 (1.0 on 2028-04-18), W3 2028-07-01 to 2029-06-30, W4 from 2029-07-01. Tiers T0 to T3 follow PRODUCT 5.3; T3 means community or later.
- UNVERIFIED in capitals is the project's own marker for code not yet checked against an outside authority.
- Section numbers after a spec link (for example [spec/finance.md](spec/finance.md) 4.1) name the section in that file.

## 3. Coverage by area

### 3.1 Accounting and invoicing

obop holds the accounting core mostly as data: a declarative double-entry ledger package, a built customer-invoice module that sales orders feed, web-shop payments and an UNVERIFIED Swedish slice (SIE 4, VAT report, bank matching; K59 to K62). Most of Odoo's strength (tax engine, bills and credit notes, automatic postings, reconciliation, reports, lock dates, multi-currency, e-invoicing, the German pack) is specified in [spec/finance.md](spec/finance.md) for W1, with assets, budgets and analytics in W3, multi-company in W2 and consolidation in W4. The gaps are depth and time, localisation breadth left to third parties, and posted entries that can still be edited.
