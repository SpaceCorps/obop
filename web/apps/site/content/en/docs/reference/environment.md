obop reads a small number of environment variables. Command line flags win over variables.

For PostgreSQL add `?sslmode=require` (or `verify-full` with `&sslrootcert=/path/ca.pem`) to encrypt the connection; see Self-hosting.                                                                                     | `sqlite://obop.db`                |
| `OBOP_TOKEN`                           | Bearer token for `obop mcp`, `obop call` and `obop commands`. Same as `--token`.                                                                                                                                                                                                                                                                           | none                              |

| `OBOP_UPDATE_FEED`                     | The release feed read when an administrator checks for updates. | `OBOP_BACKUP_DIR`                      | Where the backup taken before an update from inside the instance is written.                                                                                                                                                                                                                                                                               |
| `OBOP_MARKETPLACE_URL`                 | An extra marketplace: a host serving `index.json` and `packages/<id>.toml`. | `OBOP_BLOB_DIR`                        | Directory for uploaded pictures and files (images on products, pages, posts, documents). Default: next to the SQLite file; PostgreSQL and memory instances keep them in the database.                                                                                                                                                                      | beside the db                     |

For trials and tests only; never set it where real buyers pay.                                                                                                                                                                                                                              | off                               |

## PostgreSQL connection pool

Each process keeps small pools of connections instead of one connection behind a lock. A request that finds none free waits at most the acquire timeout and then gets `503` with `Retry-After` and `{"error":"storage_busy"}`; the same answer, with `storage_unavailable` or `storage_timeout`, tells a client that the database cannot be reached or that a statement ran into its time limit. A value that is not a number in range stops the server at start. Details, sizing and the supported poolers: Self-hosting.

| Variable                                                                       | Meaning                                                                                                                                                                        | Default                   |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| `OBOP_DB_POOL_SIZE`                                                            | Connections of the PostgreSQL pool, per process (1 to 64).                                                                                                                     | 8                         |
| `OBOP_DB_ACQUIRE_TIMEOUT_MS`                                                   | How long a request waits for a free connection before it is answered `503` with `Retry-After` and `storage_busy` (50 to 60000).                                                | 2000                      |
| `OBOP_DB_MAX_WAITERS`                                                          | Requests allowed to wait for a connection at once; more are refused immediately.                                                                                               | 256                       |
| `OBOP_DB_LONG_READS`                                                           | Scans, exports and restores allowed to run at once, so they cannot take every connection.                                                                                      | half the pool             |
| `OBOP_DB_IDLE_TIMEOUT_SECS`, `OBOP_DB_MAX_LIFETIME_SECS`                       | An idle connection is closed after this long; every connection after the second value.                                                                                         | 300, 1800                 |
| `OBOP_DB_HEALTH_CHECK_IDLE_MS`                                                 | A connection idle this long or longer is checked when it is handed out; `0` checks every time.                                                                                 | 1000                      |
| `OBOP_DB_CONNECT_TIMEOUT_MS`                                                   | Opening one connection (TCP, TLS and login).                                                                                                                                   | 10000                     |
| `OBOP_DB_STATEMENT_TIMEOUT_POINT_MS`, `_LIST_MS`, `_AGGREGATE_MS`, `_BATCH_MS` | Time limits of a point read or write, a list or search, a scan or count, and a multi-statement transaction, restore or export. `0` keeps the server's own `statement_timeout`. | 5000, 10000, 15000, 60000 |
| `OBOP_DB_IDLE_IN_TRANSACTION_MS`                                               | How long a scan or export may sit idle between two fetches before the server ends its snapshot; `0` is no limit.                                                               | 120000                    |
| `OBOP_DB_LOCK_POOL_SIZE`, `OBOP_DB_BLOB_POOL_SIZE`                             | Connections for cross-process locks (at most 8; a pool of its own) and for the blob store.                                                                                     | 8, 4                      |
| `OBOP_DB_POOLER`                                                               | `transaction` when the database address is a pooler in transaction mode, such as PgBouncer. Needs `OBOP_LOCK_DATABASE_URL`.                                                    | `direct`                  |
| `OBOP_LOCK_DATABASE_URL`                                                       | A direct `postgres://` address of the same database for the lock connections (same `sslmode` rules). A start-up check refuses an address that reaches another database.        | the database URL          |

## Control plane

Used by `obop platform serve`.

| Variable                                                         | Meaning                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OBOP_DATA_DIR`                                                  | Where the `local` provisioner keeps instance data. Default `obop-instances`.                                                                                                                                  |
| `OBOP_IMAGE` or `OBOP_REPO` (with `OBOP_BRANCH`, default `main`) | Where instance services come from with the `sliplane` provisioner. An image (`ghcr.io/spacecorps/obop:<commit>`) needs no build and wins when both are set; a repository means Sliplane builds each instance. |
| `OBOP_REGISTRY_CREDENTIAL`                                       | A Sliplane registry credential id (`sliplane credentials create ...`), for a private image.                                                                                                                   |
| `OBOP_UPGRADE_SETTLE_SECS`                                       | Seconds to let a redeploy settle before asking whether the service is live, in `obop platform upgrade-instances` (default 30).                                                                                |
| `OBOP_PLATFORM_ADMINS`, `OBOP_STATUS_INTERVAL_SECS`              | Staff emails for the forum and status console; how often the status checks run (default 60; one process per interval runs them).                                                                              |
| `OBOP_MARKETPLACE_URL`                                           | Optional extra catalog for every instance.                                                                                                                                                                    |

## Sliplane provisioner

`--provisioner sliplane` needs:

| Variable                                        | Meaning                                                                                                                                           |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SLIPLANE_ACCOUNT`                              | Account name the bundled Sliplane CLI is registered under.                                                                                        |
| `SLIPLANE_API_KEY`                              | A Sliplane API key with write access. The container entrypoint registers it with the CLI and removes it from the environment. Set it as a secret. |
| `OBOP_SLIPLANE_PROJECT`, `OBOP_SLIPLANE_SERVER` | Where instance services go.                                                                                                                       |
| `OBOP_CELL_ADMIN_URL`                           | `postgres://` superuser URL of the shared PostgreSQL server, as the control plane reaches it.                                                     |
| `OBOP_CELL_INSTANCE_HOST`                       | `host:port` that instances use to reach that server, for example `obop-postgres.internal:5432`.                                                   |

## Tests

`OBOP_TEST_POSTGRES_URL` adds PostgreSQL to `cargo test`. `OBOP_BIN` points the end-to-end suite at a built binary.
